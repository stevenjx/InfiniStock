# InfiniStock 二期规划：从"能用"到"像专业进销存"

> 更新日期：2026-11-12 · 依据：`UI/` 五张参考图 + 三轮实机反馈
> 一句话结论：一期做对了"零件"（token、组件、卡片），没做对"装配"（页面骨架、信息密度、动作入口）。

---

## 一、先定口径（已落地，后续所有数字都按这个口径）

| 项 | 口径 | 说明 |
|---|---|---|
| 商品 | **只有 MacBook** | 已删除 iPhone 相关文案、占位、种子数据、测试用例 |
| 进价 | 人民币 ¥ | 国内卖家报价 |
| 汇率 | 1 元 = N 缅币，**只填数字** | 入库时快照到每台机器，之后改汇率不动老货 |
| 运费 | 缅币 K | 批次录入总额，按台/按货值分摊，尾差归最后一台 |
| 总进价 | 缅币 K | `进价 × 汇率 + 分摊运费`，单一派生值，不存第二份 |
| 卖价 / 毛利 | 缅币 K | 毛利 = 成交价 − 总进价，折扣计入 |

**金额格式**：缅币 `K 2,250,000`（千分位、无多余小数）；人民币 `¥3,600.00`；毛利带符号 `+K 584,000` / `-K 120,000`。

## 二、为什么"还是不像专业系统"——三条根因

对照参考图，问题不在颜色，在这三处：

1. **导航是"设置面板"结构**。侧栏分四组（库存/交易/进货/客户）+ 六个子项，像配置项清单。
   参考图是**五个平铺入口**，选中项整行填充品牌色，状态筛选放在页面内的胶囊里。
2. **列表页没有"结论层"**。参考图每页顶部都有 3–4 张 KPI 卡（今日销售额 / 今日毛利 / 已售台数），
   先给结论再给明细。我们现在只有标题右侧一行小字摘要。
3. **右栏不是"操作面板"**。参考图右栏 = 照片 + 大号型号名 + 分区字段 + **底部动作条**（编辑 / 打印小票 / 标记已售）。
   我们右栏是只读字段堆叠，没有动作，也没有商品视觉主体。

> 一期把这些理解成"组件不够漂亮"，于是加了很多卡片和圆角。真正缺的是**页面装配规则**。

## 四、界面重构（U 系列）

### U1 · 侧栏扁平化（最高优先级）
- 五个入口：库存管理 / 销售记录 / 客户管理 / 采购记录 / 设置。
- 删除分组标题；行高 32；选中整行填充 `AccentBrand`，图标与文字转白。
- 底部保留店铺名 + 备份状态点。
- **验收**：点击任意入口都能打开对应页面；选中态与页面标题一致；⌘1–⌘4 仍可用。

### U2 · 列表页统一骨架
```
页面头（标题 26pt + 右侧摘要 + 主按钮）
KPI 条（3–4 张卡，仅销售/采购/客户页）
卡片 = 工具条（搜索 + 胶囊 + 排序） + 表格 + 页脚
```
- 工具条高 44，页脚高 32，与卡片同宽同圆角。
- **验收**：四个列表页的卡片上下沿对齐；切换页面不跳动。

### U3 · 表格行视觉
- 行高 44（双行单元格 48）；型号 13.5 semibold + 序列号 11 等宽灰。
- 金额右对齐、`monospacedDigit`；毛利带符号与颜色。
- 状态徽章统一 `Badge`；选中行整行浅蓝。
- **验收**：1280×800 下不出现横向滚动条；数字列小数点对齐。

### U4 · 右侧详情面板
- 结构：面板头（标题 + 关闭）→ 照片区（16:10，无图占位）→ 大号型号名 + 状态徽章 → 分区字段 → 底部动作条。
- 未选中时给"最近入库 3 台"或"下一步建议"，不留空洞。
- **验收**：`ImageRenderer` 渲染 900×1200 无空白块；动作条按钮全部可用。

### U5 · 仪表盘重排
- 4 张 KPI 卡（含环比）→ 近 7 天柱状图 → 库龄环 + 收款环 → 待办提醒（低于成本 / 电池差 / 超期）。
- **验收**：与参考图 2 的信息顺序一致；空库时有引导。

### U6 · 收尾
- 深色模式逐页过一遍；VoiceOver 标签；⌘F / ⌘N / Delete 快捷键；窗口最小 1080×720。

## 五、执行顺序与验证

每完成一个编号，必须同时满足：

1. `./scripts/verify.sh` 全绿（当前 240+ 断言）；
2. `./scripts/build.sh` 产出 `build/InfiniStock.app` 且能启动；
3. `ViewPreview` 离屏渲染对应页面，肉眼比对参考图；
4. 提交信息用英文，一次一个编号。

顺序：**U1 → P3 → U2 → P2+P1 → U4 → P4 → U5 → P5 → P6 → U3 → U6 → P7**。

理由：先改导航与页面骨架（一眼可见），再补数据字段（要动模型，放中段），最后做细节打磨。

## 六、明确不做

- 多币种、汇率历史曲线：口径已固定为"进价人民币 + 缅币记账"。
- 云同步 / 多端：无付费开发者账号，写不可验证的同步代码是负债。
- 自定义报表 / 导出 Excel 透视：CSV 已够用。
- 库存预警自动调价、供应商管理：等有真实数据再说。

## 八、执行记录（2026-11-13：布局骨架与设置）

这一轮不再加装饰，改的是三处结构性缺口。

### U7 · 详情栏可收起
原来三栏 `NavigationSplitView` 的 detail 列没有折叠开关，系统 API 也不提供「隐藏第三列」。
改成**两栏 + 自管详情面板**：页头按钮、面板标题条 ✕、⌥⌘D 三个入口，状态存 UserDefaults。
收起后列表独占整栏；展开时宽 304–420，随窗口伸缩。

### U8 · 窗口不再跑到屏幕外
`NSWindow` 的 frame 记忆在换屏/降分辨率后会把窗口恢复到可见区域之外——进程活着，屏幕上什么都没有。
新增 `WindowFrameGuard`：首次挂载时若窗口中心不在任何屏幕可见区域内、或尺寸大于屏幕，就收进主屏居中。
同时把最小尺寸从 1080×700 降到 960×620（1080p 笔记本的可见高度只有约 660pt）。

### U9 · 标题栏与画布连成一片
`toolbarBackground` 显式铺成 `SurfaceCanvas`，消掉系统窗口材质与暖白画布之间那条灰带。

### P8 · 库存页 KPI 条
页头那行「在库 5 台 · 成本 · 标价」只够报数，拆成四张卡：台数（含未标价）、占用成本、预计毛利与毛利率、平均库龄（含呆滞数），与销售/采购/客户三页同一套骨架。

### P9 · 定价建议
`PricingAdvice`：建议价 = 总进价 ÷ (1 − 目标毛利率)，库龄超 30 天后每满一周降 1%、封顶 15%，且不低于总进价。
详情页显示建议价、库龄折价、与当前标价的差额，可一键采用。纯计算，由 `verify.sh` 断言。

### S1 · 设置重做
左侧分栏（店铺 / 单据凭证 / 定价与汇率 / 数据与备份 / 关于），改完即存，不再需要点保存。
新增可用配置：默认收款方式、目标毛利率、自动备份开关、备份保留份数（落到 `BackupService`）；
只读展示待办口径与快捷键，避免同一个阈值在三个页面各有一套标准。

验证：`verify.sh` 新增 17 项断言（配置回落 4、定价建议 11、备份保留保护 2）全绿；
`build.sh` 出包，实机核对浅色/深色、收起/展开、设置分栏。

### U10 · 表格密度与机型缩略图（2026-11-13 追加）
- **列宽**：`Table` 会把剩余宽度摊给各列，最后一列最惨——「库龄」曾占到 300pt，表头贴左、数字贴右，中间全空。五张表统一在末尾加一列空占位吸收余宽，列宽回到内容量级。
- **缩略图**：型号列前加 28pt 方块，有实物照片显示照片，没有则按产品线显示 `Air` / `Pro` / `Mac` 占位，纯文字列表有了可扫读的锚点。
- **表头对齐**：实测过三条路——`TableColumn` 不提供自定义表头视图；`NSTableHeaderCell.alignment` 被 SwiftUI 的 `AppKitTableHeaderCell` 忽略；`Text` 表头无法用 `.frame` 对齐。所以数值列只能「表头靠左、数字靠右」，靠收紧列宽把误差压到可接受范围，没有为此放弃系统表格的排序与拖拽列宽。

### U11 · 详情面板按「先决策、后档案」重排（2026-11-13 追加）
- **价格带上提**：标价（或成交价）与毛利、毛利率从第 5 段提到型号下面，用品牌浅底标出；建议价并进同一条带，不再单独占一段——它本来就是价格的一部分。
- **照片只留一处**：原来顶部一块 148pt 灰块 + 底部一块 132pt 拖放区，有照片时同一张图出现两次。现在只有「实物照片」一段，无照片时压成 60pt 窄条，省下的高度还给价格与机况。
- **两列网格**：成本、机况、单据从「一行一字段」改成 `MetricGrid`（标签在上、值在下），8 个字段从 8 行压到 4 行，面板少滚一屏。
- **顺序修正**：成本段先给总进价再拆构成；已售机器不再显示回本汇率与结汇亏损（汇率风险已经兑现，留着只是噪音）。
- **未标价不再报假亏损**：标价为 0 时毛利显示「—」，而不是拿 0 减成本算出一个负毛利。
- 建议说明改成「目标毛利率 15% 反推」——原来会把反推的原始金额（K 1,843,529）和取整后的建议价并排显示，两个数差几百反而添乱。

### P10 · 库存周转（2026-11-13 追加）
- **可售天数**：在库 ÷ 近 30 天日均销量，回答「这批货还能卖多久」。窗口内没有成交时不报 0 天（那会被读成「马上卖完」），而是显示「—」。
- **型号售速**：按型号列出售出 / 在库 / 可售天数，卖不动的型号排最前——那是最该降价或清仓的。
- **滞销占用**：库龄超 60 天的在库成本合计，与「待办」同源。
- 只从现有记录推导：售出台数用 `soldAt`（退货后 `soldAt` 被清空，机器回到在库，不算卖过），不引入历史快照表。
- 同时修正统计窗口：`Window("统计")` 没有默认尺寸，会以 900×450 打开，KPI 行在这么矮的高度里排不出来；补 1060×820 默认尺寸、最小 780×560，并加 `WindowFrameGuard`。

### P11 · 列表选中后的动作回路（2026-11-13 追加）
- **动作条**：选中行后，表格脚注变成本地动作条（品牌浅底），给出「查看详情 / 改标价 / 出库销售 / 取消选择」。原来唯一的出口在页头，隔着整张表。
- **改标价**：从列表直接打开 `ItemEditSheet`，不必先进详情。
- **右键菜单**：只有一台时给「查看详情 / 改标价」，任意选择给「出库销售 / 复制序列号 / 复制型号」。原来的「选择并出库」只是选中，名不副实，换成真正开单。
- **双击行展开详情**：放弃。实测 `Table` 上的 `onTapGesture(count: 2)` 不会触发——点击被底层 NSTableView 吃掉（探针里选中生效、手势从未回调）。要做只能给 NSTableView 挂 `doubleAction` 并按 `clickedRow` 反查数据，排序一变就错位，代价大于收益。改为动作条与右键菜单里的「查看详情」。

### U12 · 详情栏动效（2026-11-13 追加）
- **去掉位移过渡**：原来 `.move(edge: .trailing)` 和容器变窄同时进行，看起来像面板从内容底下抽出来。改成只淡入，宽度由容器插值。
- **列宽不跟着抖**：宽度插值时只有表格末尾那列空占位在变，其余列宽度不动——这是 P0 加空列顺带换来的。
- **曲线统一**：`withAnimation(.snappy)` 和 HStack 上的 `.animation` 各用一条曲线，会互相打架；现在只保留 HStack 上的 `.easeOut(duration: 0.18)`。
- **尊重「减弱动态效果」**：系统开了这项就传 nil，直接切换。
- **切换机器回到顶部**：`ScrollView.id(item.persistentModelID)`。原来在上一台滚到照片位置，选中下一台还停在那里，型号与价格被滚出视野。
- **切换按钮有状态**：开着时图标用品牌色，收起时退回次要灰，不用看面板也知道当前状态。
