# InfiniStock UI 开发规划

> 依据：`UI/` 目录 5 张参考图（1920×1200）
> 现状：16 个视图文件、108 处样式调用、12 处硬编码颜色，无统一 token
> 目标：统一视觉语言，同时保持 macOS 原生交互

---

## 一、从参考图提取的设计语言

五张图（库存 / 仪表盘 / 采购 / 销售 / 客户）共用同一套语言，不是五种风格：

| 维度 | 规格 |
|---|---|
| 整体 | 浅色、低饱和、大量留白，白卡片浮在浅灰底上 |
| 主色 | 蓝 `#2F6FEB`，只用于主操作与选中态，不做大面积填充 |
| 状态色 | 绿（在库/完成/正毛利）、橙（待入库/部分退货）、红（低于成本/亏损）、灰（已售/沉睡） |
| 卡片 | 圆角 12，1px 极淡描边 + 极轻阴影，不用重投影 |
| 徽章 | 胶囊形，两种变体：描边（在库、已入库）与浅填充（已售、待入库） |
| 表格 | 行高约 52，单元格双行（主标题 13 + 序列号 11 灰），表头灰字，选中行浅蓝底 |
| 数字 | KPI 28 bold，金额等宽数字右对齐，正毛利带 `+` 前缀 |
| 标题 | 页面标题 26 semibold，右上角一行灰色统计摘要 |
| 检查器 | 右侧独立栏，商品图 + 标题 + 徽章 + 分节 label/value + 粘底双按钮 |

这套语言可以直接用。但下面三件事必须改。

## 二、不能照搬的三处

参考图是 web 后台审美，照搬到 macOS 会"不像 Mac App"：

| 参考图做法 | macOS 应该怎么做 | 为什么 |
|---|---|---|
| 底部分页「‹ 上一页 1/4 下一页 ›」 | 去掉，改为滚动 + 表格虚拟化 + ⌘F 即时过滤 | Mac 用户不翻页，习惯滚；分页还会让 ⌘F 变得无意义 |
| 整窗一张大圆角卡片 + 窗口投影 | 用原生 `NavigationSplitView` 分栏 + 系统材质，只给内容卡片留阴影 | 窗口装饰由系统画，自己画会出现双层圆角、阴影穿帮 |
| 侧栏放「设置」，处处蓝色实心按钮 | 设置进应用菜单（⌘,），一屏最多一个 `borderedProminent` | macOS 有明确的菜单约定与主次层级，全蓝按钮等于没有重点 |

另外两点：参考图的「客户管理」和「采购记录」在当前数据模型里是**派生**而非实体（客户从单据聚合、采购即批次），规划里我会标清楚，不假装已有。

## 三、最大的前提：你是深色模式

```
AppleInterfaceStyle = Dark
系统 macOS 27.2　　参考图全部为浅色
```

如果按图硬编码浅色，**在你自己机器上第一次打开就是错的**。所以顺序必须是：

> 先建语义色层 → 再做页面。反过来做，每个页面都要返工两遍。

现有 12 处硬编码颜色（`Color.orange`、`.red`、`.opacity` 等）全部要收进 token，浅色/深色各自一套值，靠 `Color(nsColor:)` 或 asset 目录的 Appearance 自动切换。

## 四、设计 Token（浅 / 深两套）

| Token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `surface.canvas` | `#EFF1F4` | `#16181B` | 窗口底 |
| `surface.card` | `#FFFFFF` | `#22252A` | 卡片/表格底 |
| `surface.sidebar` | `#F7F8FA` | `#1C1F23` | 侧栏 |
| `surface.selected` | `#E6EDFA` | `#2A3550` | 选中行 |
| `text.primary` | `#1B1B1F` | `#E9EBEE` | 正文 |
| `text.secondary` | `#7A7F87` | `#9AA0A6` | 次要/序列号 |
| `text.tertiary` | `#A8ADB5` | `#6E747C` | 占位符 |
| `border.hairline` | `#E6E8EC` | `#31353A` | 1px 描边 |
| `accent.brand` | `#2F6FEB` | `#4C8DFF` | 主操作 |
| `status.ok` | `#1F9D5F` | `#35C07F` | 在库 / 完成 / 正毛利 |
| `status.warn` | `#E0912F` | `#F0A93B` | 待入库 / 部分退货 / 超期 |
| `status.danger` | `#D93A40` | `#FF6B6B` | 亏损 / 已全退 |
| `status.neutral` | `#8A9099` | `#868C94` | 已售 / 作废 |

圆角：卡片 12、输入框 8、徽章 999、检查器区块 10。
间距：8 基准，卡片内边距 16，卡片间距 12。
字体：系统 SF Pro；金额与序列号一律 `.monospacedDigit()` 保证纵向对齐。

状态映射（直接对应现有 `ItemStatus` / `Order.statusLabel`）：

| 业务状态 | Token |
|---|---|
| 在库 / 有效 | `status.ok` |
| 锁定 | `status.warn` |
| 已售 / 已作废 | `status.neutral` |
| 部分退货 / 超期未售 | `status.warn` |
| 已全退 / 毛利为负 | `status.danger` |

## 五、组件清单（先做组件，再拼页面）

1. **KPI 卡**：彩色图标块 + 小标签 + 28pt 数字 + 可选涨跌行
2. **状态徽章**：描边 / 浅填充两变体，输入为语义 token 而非颜色
3. **双行单元格**：主标题 + 灰色序列号，用于所有列表
4. **分节详情**：label 左灰、value 右黑，节标题 11pt 灰
5. **检查器容器**：标题栏 + 可滚动内容 + 粘底操作区
6. **警示卡**：四种语义底色（红/橙/黄/灰），左图标 + 标题 + 两行元信息
7. **空状态**：图标 + 一句说明 + 一个主操作，替代现在的 `ContentUnavailableView` 默认样式
8. **图表**：柱状（销售额/毛利双色）、环形（库龄构成、收款方式），用系统 `Charts`

## 六、分期

### U1 · 设计系统层 ✅ 已完成

新增 `InfiniStock/Design/`：`Tokens.swift`（颜色/圆角/间距/字体）、`Badge.swift`、`StatCard.swift`、`SectionHeader.swift`，并在 asset 目录补 `AccentColor`。

**验收**：`grep -rE "Color\.(red|orange|blue|green)|\.opacity\(" Views/` 结果为 0；浅色与深色各截一张图，无对比度不足的文字。

### U2 · 库存主表 ✅ 已完成

双行单元格、状态徽章、列宽收敛（当前 8 列在 1080p 上要横向滚动）、悬停高亮、选中态、行高 52-56。保留 `Table`（有排序与列拖拽），不用 List 重写。

**验收**：在 1080p 宽度下 型号/序列号/规格/成本/标价/库龄 六列完整可见；⌘F 过滤即时无分页。

### U3 · 详情与检查器 ✅ 已完成

详情页从 `Form` 改为分节卡片；检查器改为「商品图 + 标题 + 徽章 + 分节 + 粘底操作」；照片区按参考图的圆角图框重做。

**验收**：详情与检查器在浅/深两模式截图风格一致；照片为空时有明确拖拽提示区。

### U4 · 仪表盘 ✅ 已完成

KPI 四卡（今日销售额/今日毛利/在库台数/库存总值）+ 近 7 天柱状图 + 库龄环形图 + 收款方式环形图 + 警示卡区（低于成本、超期未售）。数据全部来自现有 `InventoryStatistics`，只需补 7 天序列与收款方式聚合。

**验收**：图表数值与 `scripts/verify.sh` 里的统计断言一致；空数据时显示空状态而非空白图表。

### U5 · 单据 / 批次 / 客户 ✅ 已完成

单据列表套用双行单元格与状态徽章；新增批次列表页（模型已有，缺页面）；客户列表从单据聚合（按姓名+电话去重），**不新增数据模型**。

**验收**：退 1 台的单在列表显示「部分退货」橙色徽章；客户聚合数与单据去重后一致。

### U6 · 无障碍与细节 ✅ 已完成

`Reduce Motion` / `Reduce Transparency` 适配；焦点环可见；VoiceOver 标签补全；全键盘可达（已有 ⌘N/⌘F/⌘⇧S/⌘P/⌫）。

**验收**：开启「减弱动态效果」后无动画闪烁；纯键盘完成「入库→查→出库→打印」。

| 仪表盘 | 统计窗口 | ✅ 已有，缺 7 天序列与收款聚合 |

## 八、明确不做

- 不自己画窗口标题栏和红绿灯按钮
- 不引入第三方 UI 库（图表用系统 `Charts`）
- 不为了"像参考图"而恢复分页、加装饰性渐变、加无意义的悬浮动画
- 不在 U1 完成前改任何页面——否则每个页面要返工两遍

## 九、风险

1. **深色模式返工**：这是当前最大的现实风险，U1 必须先落地并在双模式下验收。
2. **信息密度下降**：参考图行高 52 比现在的 `Table` 高，一屏能看到的机器变少。缓解：提供紧凑模式开关。
3. **图表数据缺口**：7 天序列需要按日聚合历史单据，现有 `InventoryStatistics` 只算今日。
4. **客户聚合的歧义**：同名不同人、同人不同电话。默认按「姓名 + 电话」组合键，允许手工合并（需新页面，暂不做）。

| 阶段 | 结果 | 验收证据 |

| U2 | 主表双行单元格、状态徽章、6 列不横向滚动 | 1080p 实机截图 |

| U5 | 侧栏四分区；单据重做；批次与客户新增页面 | 实机截图；8 项客户聚合断言 |
| U6 | 无障碍标签 + ⌘1–⌘4；清除全部硬编码颜色 | grep 审计为 0 |

断言数：206 → **228**。

### 过程中发现并修掉的问题

1. `Token.Type` 与 Swift 元类型同名，编译器无法区分 → 改名 `Typography`。
2. 详情页渲染成空白 → `ImageRenderer` 无法布局 `ScrollView` 内容，把内容抽成 `ItemDetailContent`。
3. 照片拖放区出现黄色角块 → 是 `.onDrop` 的目标提示装饰，只在真实拖拽时出现，非缺陷。
4. 仪表盘 KPI 卡在窄宽度换行、亏损显示成负数 → 调整最小宽度、改成正向表述「每台亏 X」。
5. 各表单残留 7 处硬编码颜色 → 全部替换为语义 token。

### 未做（有意）

- 自定义窗口标题栏与红绿灯：由系统绘制更稳，自绘会有双层圆角与阴影穿帮。
- 分页：Mac 用户习惯滚动 + ⌘F，分页会让搜索失去意义。
- 悬浮/渐变装饰动画：与 macOS 原生观感冲突。

## 十一、页面骨架二期（对照参考图补齐）

上一轮（U1–U6）换的是组件与结构，但列表页最显眼的骨架仍然缺失，所以观感变化有限。这一轮补的是骨架：

| 新增 | 作用 |
|---|---|
| `FilterBar` + `SearchField` + `FilterPillGroup` | 搜索、状态胶囊、排序从工具栏挪进卡片顶部，四个分区同构 |
| `TableFooter` | 卡片底部的条数与选中汇总，卡片有头有尾 |
| `PanelHeader` / `PanelFooter` / `PanelSection` | 右栏改成「标题条 + 分隔线分节 + 底部操作条」的检查器结构 |
| `PageHeader` 操作区 | 入库/出库/更多进页面头，窗口工具栏清空，页面从内容开始 |
| 侧栏品牌区 + 设置 + 备份状态 | 侧栏不再是纯导航列表 |

同时修掉两处真实问题：

- 内容区实际只有约 450pt，日期列用系统本地化格式（`2026/11/12 中午12:58`）会被截断，统一改为 `yyyy-MM-dd HH:mm`。
- 单据/批次/客户三个分区各自保留了 `navigationTitle`，与页面头重复，已移除。

验证：228 项业务断言全绿；浅色与深色实机截图逐一确认。
