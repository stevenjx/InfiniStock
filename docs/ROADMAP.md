# InfiniStock 开发规划（macOS 优先）

> 更新日期：2026-11-11 · 当前阶段：M1–M6 已完成并通过自检，M7 阻塞（缺付费开发者账号）

## 一、范围决策

| 项 | 决定 | 原因 |
|---|---|---|
| 平台 | **仅 macOS** | 无付费开发者账号，iPhone 免费签名 7 天过期，无法作为日常经营工具；macOS 本地签名可长期自用 |
| 同步 | **暂缓** | CloudKit 需要付费会员（¥688/年）。数据层已按"本地优先"设计，未来接入不需要重构模型 |
| 架构 | 单 App、单数据库、无后端 | 一个人用，不需要服务端 |
| iOS 代码 | 保留在 `#if os(iOS)` 分支中，不参与编译 | 未来恢复时不用重写；代价是这部分代码会随迭代腐烂，恢复时需重测 |

## 二、不可动摇的技术原则

1. **库存是派生量**，不存数量字段。`在库数 = count(status == .inStock)`，避免任何计数漂移。
2. **金额全程 `Decimal`**，落地成本在入库时快照，之后不随汇率浮动。
3. **序列号唯一性由应用层校验**，不用数据库约束（一旦将来开 CloudKit，唯一约束不可用）。
4. **同步层不承担业务逻辑**。顺序是：先写对本地，再叠加同步。
5. **零第三方依赖**。这个体量引入库只会扩大维护面。

## 三、里程碑

每个里程碑结束时必须产出一个可双击运行的 `build/InfiniStock.app`。

### M1 · 本地销售闭环 ✅ 已完成
数据模型（Item / Order）、入库查重、出库、毛利、派生库存、双栏界面。
**验收**：17 项断言通过；真实录入 10 台无异常；两端编译通过。

### M2 · macOS 工作台 ✅ 已完成
三栏 `NavigationSplitView`（导航 / 列表 / 详情）+ 右侧 `.inspector()` 成本检查器；列表可排序、列宽可拖；多选批量出库；修复工具栏"统计"按钮溢出（当前藏在 `»` 里）。
**验收**：全键盘完成"入库一台 → 找到它 → 出库"；窗口缩到 900pt 宽时工具栏无溢出。

### M3 · 照片与销售凭证 ✅ 已完成
拖拽/选择照片存入 `.externalStorage`；销售凭证用 Core Graphics 直绘矢量、`ImageRenderer` 出 PDF；系统分享与 A4 打印。
> 注意：法律上是**销售凭证/收据**，不是发票。真电子发票需对接税务服务商。
**验收**：导出 PDF 放大 400% 边缘无锯齿；金额与小写大写一致；打印页边距正确。

### M4 · 成本精算 ✅ 已完成
批次入库；运费按台数或货值分摊；汇率在批次创建时锁定；批次内单台落地成本可追溯到分摊公式。
**验收**：一个 10 台批次、运费 500、按货值分摊，各台成本之和恰好等于批次总额（无分位误差）。

### M5 · 统计与库龄 ✅ 已完成
库存总值、今日销售额、毛利率；库龄列与超期标红；呆滞品降价建议。
**验收**：手工核对 3 组数据一致；库龄按自然日计算，跨时区不错位。

### M6 · 平台级能力 ✅ 已完成
App Intents（全局搜索序列号）、Spotlight 索引（`IndexedEntity`）、全局快捷键（⌘N 入库 / ⌘F 搜索）、Touch ID 鉴权（改价、删单）。
**验收**：Spotlight 输入序列号能直接打开对应机器；未通过 Touch ID 无法完成改价。

### M7 · 同步 ⛔ 阻塞，未实现

**阻塞原因（不可绕过）**：
1. CloudKit 及推送属于付费 Apple Developer Program 才开放的 capability，免费账号签名直接失败。
2. 因此无法创建容器、无法在真机验证双向同步，**任何实现都无法验收**。
3. 按"不做无法验证的代码"的原则，本期未写任何同步逻辑，避免留下无法证伪的假实现。

**解除阻塞后按此顺序做**：
1. 付费账号 → 在开发者后台创建容器 `iCloud.com.infinistock.app`。
2. 解开 `InfiniStock.entitlements` 中 iCloud 三项注释。
3. 构建设置 `SWIFT_ACTIVE_COMPILATION_CONDITIONS` 加入 `CLOUD_SYNC`。
4. 模型层无需改动：属性均有默认值、关系均可选、无唯一约束。
5. 补冲突处理：按 `(soldAt, originDeviceID)` 定序，冲突单标记为"待确认"，绝不静默覆盖。

**验收（账号到位后执行）**：Mac 与 iPhone 同时对同一序列号出库，联网后一端成功、另一端弹出冲突提示，库存总数不重复扣减。

## 四、开发流程

```bash
./scripts/build.sh                  # 构建 build/InfiniStock.app（Debug）
./scripts/build.sh Release          # 构建 Release
./scripts/verify.sh                 # 业务层自检（66 项断言，不开界面）
open build/InfiniStock.app          # 直接跑
```

- `build/` 是产物目录，不进版本库。
- 若命令行报宏插件错误 `malformed response`，说明环境禁止 `sandbox-exec`，用 `SWIFT_NO_SANDBOX=1 ./scripts/build.sh`。
- 提交规范：Conventional Commits，**英文**。`feat: ...` / `fix: ...` / `chore: ...` / `docs: ...`。一个功能一个 commit。

## 五、已知问题

- 表格列较多，在 1080p 屏上需要横向滚动；Mac 原生 Table 支持拖拽列宽与横向滚动。
- `#if os(iOS)` 相关视图已在 M2 移除，恢复 iOS 需重写根视图，但 Model / Store 层可直接复用。
- 无 `CLOUD_SYNC` 时统计页显示"本地模式"提示条，属预期行为。
- Touch ID 与 Spotlight 只能人工验收：前者会弹系统验证框，后者需在系统聚焦里搜序列号。
- Debug 构建可用 `seed.flag` 注入样例数据，Release 不包含这段代码。

## 六、第二期计划（P0–P4）

> 起始状态：M1–M6 完成，66 项断言全绿。第二期不再加新模型，只补"能真正开店用"的缺口。

### 反向清单（本期明确不做）

- **不做云同步**：M7 阻塞于付费账号，做出来无法验收。
- **不重构现有 Store 层**：66 项断言在保护它，动了就要重跑全部验收，收益为零。
- **不做多人/多店/权限**：那是另一个产品，不是这一期的缺口。

### P0 · 数据安全 ✅ 已完成（98 项断言全绿）

现状：数据只存在于 `~/Library/Containers/com.infinistock.app/Data/Library/Application Support/default.store`，磁盘故障或误操作即全丢，且没有任何导出手段。

- 全量导出：JSON（可回灌）+ CSV（给 Excel 看）
- 自动备份：每天首次启动写一份快照到 `~/Documents/InfiniStockBackups/`，保留最近 14 份
- 恢复：从 JSON 回灌并校验条数

**验收结果**：全部通过。
- `1234.56` / `0.01` / `8888.88` 经 JSON 往返后逐字一致（金额以字符串编码，不经过 Double）
- 清空后回灌：台数、序列号集合、落地成本合计、成交额合计全部相等
- 重复回灌不叠加（幂等）
- 损坏文件与未知版本被拒绝
- CSV 带 BOM，Excel 打开中文正常，行数 = 表头 + 机器数
- 保留策略：20 份文件只留最新 14 份，最旧被删
- 真实写盘 + 回读通过

**一个平台约束**：macOS 沙盒不允许直接写 `~/Documents`。备份目录必须由你在系统文件面板授权一次，App 存下安全作用域书签后才能持续写入。这是系统限制，不是实现偷懒。

### P1 · 真正能开单 ✅ 已完成

- 单号改为连续序号 `SO-2026-0001`，跨年重置，带并发防重
- 凭证模板可配：店名、电话、地址、收款方式、保修期，存本地设置
- 批量出库支持逐台改价（现在只能统一按标价）
- 折扣 / 抹零，并在凭证上单独一行体现

**验收结果**：全部通过。
- 单号 `SO-2026-0001/0002/0003` 连续不跳号，失败的单不占号
- 三台不同价 6800/5500/4200 + 折扣 200 + 抹零 88 → 应收 16212，与大写一致
- 毛利按**实收**计算（16212 − 12000 = 4212），折扣不会被忽略
- 凭证印出店名、电话、地址、折扣行、抹零行、收款方式、可配保修天数
- 恢复备份后继续下单接着 0004，不重号
- 统计改为从单据取收入与毛利，作废单不计入

### P2 · 对账与单据 ✅ 已完成

- 单据列表：按日期、客户、金额筛选，可进入详情重出凭证
- 按客户名搜索（现在只能搜序列号与型号）
- 部分退货：一单三台退一台，其余不受影响

**验收结果**：全部通过。
- 单据列表：按日期倒序，可按单号 / 客户 / 联系方式 / 序列号搜索，按 有效 / 有退货 / 已作废 筛选
- 侧栏新增「交易 › 单据」，选中后右侧显示详情，可直接重出凭证或退货
- 部分退货：退一台 4200 → 小计 16500→12300，折扣与抹零按剩余货值比例保留，应收与毛利同步重算
- 全部退完：应收/毛利/折扣精确归零，单据标记作废但保留，状态显示「已全退」以区别于手工作废
- 退回机器回到在库、清空成交信息，库存台数自动恢复（派生量，无需额外维护）
- 非本单机器、已作废单再退，一律拒绝
- 凭证新增红色售后行：「本单已退货 N 台，退回 X，上述金额为退货后净额」
- 备份格式升 v3，退货台数与金额随备份往返

### P3 · 批量与迁移 ✅ 已完成

- CSV 导入，覆盖型号/芯片/内存/存储/颜色/成色/序列号/进价/币种/汇率/运费/标价
- 导入预检：重复序列号、非法金额逐行报错，**先报错不写入**

**验收结果**：全部通过。
- 100 行含 3 行错误 → 97 台入库，库中确实 97 条，错误行未入库
- 错误行号精确（第 2/24/89 行），可导出 CSV 清单
- 同一文件重导 → 100 行全部报「库中已存在」，零重复
- Excel 风格文件（CRLF + BOM + 字段内逗号）100 行 2 错 → 98 台，颜色「深空黑, 沙漠色」完整保留
- 预检不写库；带批次导入会重算运费分摊
- 模板见 `docs/导入模板.csv`

**过程中发现并修掉一个真实缺陷**：首版按 `Character` 遍历解析，而 Swift 把 CR+LF 合并成一个字素簇，导致 Excel 导出的 CSV 被整份读成一行。改成按 Unicode 标量解析后才正确，此坑已记入代码注释。
